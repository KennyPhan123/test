This is a basic overview of biomes and their creation. As well as different places that a biome is taken into consideration.

== BiomeDef ==

Biomes are defined in XML using <code>BiomeDef</code> [[Modding_Tutorials/Defs|Defs]]. As with all Defs, looking at the vanilla examples is a great way to get a feel for how the system is used.
In order to generate a biome on the world map, biomes also require a unique <code>workerClass</code> defined in code. See [[Modding_Tutorials/Setting_up_a_solution|Setting up a solution]] to get started.

=== Fields ===

The following are valid fields in <code>BiomeDef</code>. Not all fields are necessary, look at vanilla BiomeDefs for examples.

== Determining Biome ==

Biome calculation is done during world generations <code>WorldGenStep_Terrain</code>. Each tile is calculated individually. After verifying the biome can be placed via the BiomeDefs <code>generatesNaturally</code>, and the BiomeWorkers <code>CanPlaceOnLayer</code>, it's score is calculated from the individual biome workers <code>GetScore</code>. The biome with the highest score will be placed on that specific tile. Note that BiomeWorkers should be unique. If two biomes are using the same biomeWorker or have the same score, the first mod loaded according to load order wins. 

=== Biome Generation ===

There is no right or wrong way to create the score for biomes. If you look at biome workers, many of them will use different formula or logic to appear on the map. Here is an example used from the mod [https://github.com/Halicade/GuldenBiome/blob/master/Source/BiomeWorker.cs| Gulden Biome (Continued)].

<source lang="cs">
// We are subclassing the temperate forest biome worker
public class BiomeWorker_GuldenForest : BiomeWorker_TemperateForest
{
  public override float GetScore(BiomeDef biome, Tile tile, PlanetTile planetTile) {
    // We don't want to completely overwrite the parent biome. 
    // That's why we only want tiles with an elevation between 500 and 800.
    if (tile.elevation is <= 500 or >= 800) {
        return 0;
    }
    
    // Get what the score is of the parent biome, temperate forest
    float score = base.GetScore(biome, tile, planetTile);
    // If that score is 0 or less we don't want this biome there.
    if (score <= 0) {
        return 0;
    }
    
    // We add 1.5 so that it is higher than the temperate forest.
    // We don't want this number too large, otherwise it will overwrite other biomes.
    return score + 1.5f;
  }
}
</source>

=== Using Rand ===

If you want a biome to appear randomly around the world map, you need to seed your Rand value. Without this, if you were to regenerate the world using the same world seed, your biome would appear in different tiles. You can use <code>Rand.PushState</code> and <code>Rand.PopState</code>. Or you can use <code>Rand.ValueSeeded</code> or any other method that allows for a seeded outcome. This below example comes from multiple different sources and was rewritten here for better understanding.

<source lang="cs">
public class BiomeWorker_MyCustomBiome : BiomeWorker
{
    public override float GetScore(BiomeDef biome, Tile tile, PlanetTile planetTile) {
        // We don't want to generate on water.
        if (tile.WaterCovered) {
            return -100f;
        }
        // We don't want to generate where it's too cold
        if (tile.temperature < -10f) {
            return 0f;
        }
        //We don't want to generate where there is little rain
        if (tile.rainfall < 600f) {
            return 0f;
        }
        
        // We use the tileId as part of the seed to get a constant for each tile.
        // "^" is to perform a bitwise XOR operation
        // 0x11245d7a is a random hexadecimal value
        // We add these last two pieces so that if another mod randomly generates their tiles, the values won't be the same
        // If our random value is above 0.009 we won't generate here
        // This might seem like a small amount, but there is over 100,000 tiles on a map with 30% coverage so the odds are quite high
        if (Rand.ValueSeeded(planetTile.tileId ^ 0x11245d7a) > 0.009f) {
            return 0f;
        }
        
        // A formula to calculate the score at this tile.
        return 16f + (tile.temperature - 7f) + (tile.rainfall - 600f) / 180f;
    }
}
</source>

== About Terrain modifiers ==

There are many terrain modifiers like <code>lakeBeachTerrain</code> and <code>gravelTerrain</code>. These are used by MapGenUtility to get the appropriate terrain at a specific cell. These can change depending on if you have a [[Landmarks#Mixed_biome|mixed biome]]{{OdysseyIcon}} or a <code>tileMutatorDef</code> that overrides a terrain such as <code>overrideLakeBeachTerrain</code>. Note that not every terrain modifier has an equivalent override. Some specific terrain may be hardcoded.

== Places That Use Biomes ==

In addition to the fields required for biomes, some feilds require knowledge of the biome to trigger specific events or occurences. In these cases a [[Modding_Tutorials/PatchOperations|patch operation]] will be necessary

=== Animals and plants ===

Animals and plants can also set where they spawn in their raceProperties and plantProperties respectively. Duplicates are not allowed between the biome and properties list. Either method is acceptable for appearance rates. However, you are not able to set their pollution appearance rate or coastal appearance rate through their properties. If you are creating a biome, it might be more sensible to place the appearances in the <code>BiomeDef</code>.

=== <code>IncidentDef</code>s ===

<code>Ambush</code>, <code>ManhunterAmbush</code>, <code>CaravanMeeting</code>, and <code>CaravanDemand</code> requires a biome listed in their <code>mtbDaysByBiome</code> to be considered a valid map to have their incidents occur.

Some incidents have <code>allowedBiomes</code> or <code>disallowedBiomes</code>. [[Events#Beavers!|Alphabeavers]] for example can only appear in the Tundra or Arid Shrubland. Affected incidents include <code>AmbrosiaSprout</code>, <code>HerdMigration</code>, <code>Alphabeavers</code>, <code>VolcanicAsh</code>, <code>LavaEmergence</code>{{OdysseyIcon}}, <code>LavaFlow</code>{{OdysseyIcon}}, <code>VolcanicDebris</code>{{OdysseyIcon}}, <code>BoomshroomSprout</code>{{OdysseyIcon}}, <code>BioluminescentSpores</code>{{OdysseyIcon}}, <code>DroughtInitial</code>{{OdysseyIcon}}, and <code>Drought</code>{{OdysseyIcon}}

<code>GauranlenPodSpawn</code>{{IdeologyIcon}} is the only incident that makes use of <code>disallowedBiomes</code>.

=== <code>FeatureDef</code>s ===

<code>FeatureDef</code>s generate names that can appear alongside landforms on the world map. These are things like "Barra Sea", "Bat Cheek Flats", and "Gorar Desert". Some <code>FeatureDef</code>s have <code>rootBiome</code> and <code>acceptableBiome</code>. For example, the <code>Desert</code> FeatureDef has <code>Desert</code> and <code>ExtremeDesert</code> as <code>rootBiomes</code> meaning at least one of these are required for an area to be given this name. <code>acceptableBiomes</code> are adjacent biomes that can also fulfill the qualifications for the Desert Feature. This is purely for visual and does not have impact on gameplay.

=== <code>TileMutatorDef</code>s ===
Most <code>TileMutatorDef</code>s in Odyssey will not be active on a biome unless they are patched into the TileMutatorDefs <code>biomeWhitelist</code>. You can also restrict certain biomes using the <code>biomeBlacklist</code>. [[Modding_Tutorials/Mod_Folder_Structure#LoadFolders.xml_.28Optional.29|LoadFolders]] is recommended here.
